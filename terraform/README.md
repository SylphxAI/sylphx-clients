# terraform-provider-sylphx

The Sylphx Terraform provider (`sylphxai/sylphx`; the Registry namespace is the GitHub owner, `SylphxAI`): every Sylphx Resource type
with a declarative spec is a resource and a data source, over the one API at
`https://api.sylphx.com`. Design: `docs/specs/one-platform/resource-api-and-clients.md` §8.6.

```hcl
provider "sylphx" {
  # api_key defaults to SYLPHX_API_KEY; base_url to SYLPHX_BASE_URL.
  org     = "org_hk0101j9"
  project = "prj_hk0101j9"
  env     = "env_hk0101j9"
}

resource "sylphx_data_database" "main" {
  database_id = "main"
  spec        = { compute_units = 1, deletion_protection = true }
}

data "sylphx_events_topic" "orders" {
  name = "orgs/org_hk0101j9/projects/prj_hk0101j9/envs/env_hk0101j9/topics/orders"
}
```

## Mapping

| Schema | Terraform |
| --- | --- |
| Resource `{service}.sylphx.com/{Kind}` (`terraform: true`, SPEC_STATUS) | resource and data source `sylphx_{service}_{kind}` |
| `spec` fields | the `spec` object: REQUIRED fields are required, the rest optional and computed (the API fills defaults; an unset value keeps its prior state) |
| `status`, `uid`, `meta.etag`, `meta.generation`, times | computed |
| `meta.labels`, `meta.annotations`, `meta.display_name` | `labels`, `annotations`, `display_name` |
| `IMMUTABLE` (or no Update method) | forces replacement |
| `sensitive` | `Sensitive`; `INPUT_ONLY` values are write-only and keep their configured value in state |
| `name` | `id`, `name`, and the import id |
| parent, caller-chosen id | `parent` (default from the provider's `org`/`project`/`env`) and `<kind>_id`; both force replacement |
| reconciled types | every mutation waits on its Operation within `timeouts` (default 20m) |

CRUD is the standard methods: Create sends the caller-chosen id; Read uses
Get, and `NOT_FOUND` removes the resource from state; Update sends a PATCH
with an explicit `update_mask` from the plan diff and the last-read etag as
`If-Match`; Delete sends the etag (the API enforces `deletion_protection`).
`plan` runs each create and update with `validate_only`, so server-side
validation fails at plan time. Errors carry the API's `code`, `detail`, and
request id.

## Layout

| Path | Is |
| --- | --- |
| `internal/generated/` | Generated by `sylphx-gen` from `contracts/`: one `def.Resource` table per type and the field tables of its messages. Do not edit. |
| `internal/def/` | The table vocabulary. |
| `internal/provider/` | The provider: schema mapping, wire conversion, generic CRUD, import, plan-time validation. |
| `internal/client/` | The HTTP client: bearer auth, one Idempotency-Key per logical call, retries with full jitter, problem bodies, Operation waits. |

## Develop

```sh
go build ./... && go vet ./...
go test ./...   # with a terraform CLI on PATH (or TF_ACC_TERRAFORM_PATH), the
                # lifecycle tests drive real terraform against an in-memory API
```

Regenerate the tables after a schema change with `cargo run -- generate` in
`tools/sylphx-gen`.

## Publishing

Registries publish only from a public repository named
`terraform-provider-sylphx`, under the namespace of its GitHub owner:
`SylphxAI/terraform-provider-sylphx` is `sylphxai/sylphx` on
registry.opentofu.org (and, later, registry.terraform.io).

1. Tag `clients/terraform/v0.x.y` on main in SylphxAI/cloud.
2. `.github/workflows/mirror-publish.yml` splits this directory
   (`scripts/mirror-split.sh`, deterministic, history kept), checks it (MIT
   `LICENSE`, `README.md`, denylist, gitleaks), fast-forwards the mirror's
   `main`, and pushes the tag `v0.x.y` there.
3. Its `terraform-release` job checks out the mirror at that tag, tests it,
   and runs goreleaser (`.goreleaser.yml`), which creates the mirror's GitHub
   Release: zips, `SHA256SUMS`, its GPG signature, and the manifest. It
   publishes only while the `TERRAFORM_GPG_PRIVATE_KEY` and
   `TERRAFORM_GPG_PASSPHRASE` secrets exist in SylphxAI/cloud.

Releases are signed with the RSA-4096 key in [`signing-key.asc`](signing-key.asc)
(fingerprint `BD72CA557CC6A8ABBA9F45F2242632127A587E4C`). The OpenTofu registry indexes new tags of the mirror
once the provider and this key are registered through its issue forms
(opentofu/registry, "Submit new Provider" and "Submit new Provider Signing
Key"; the forms are the only accepted channel).

Live acceptance tests (§12: apply, plan with no diff, import, destroy
against a test org) run once `api.sylphx.com` serves the Resource API.
